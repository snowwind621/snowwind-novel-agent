# 雪风小说工坊 · 架构说明

## 一句话

这是一个「以 AI 为主体」的长篇小说工作台：**事实在文件里，判断在智能体里，界面只负责让人随时能插手。**

## 三条铁律

### 1. 一个事实只存一处

正文只在 `正文/`；会随章节变的数据只在 `台账/`；
稳定设定只在 `设定/` 与设定面板。别的文件提到它们时只写指针，不抄第二份。

这条不是形式主义：两份拷贝早晚改一边忘另一边，而长篇小说的崩坏都是从「同一个数字有两个版本」开始的。

### 2. 文件是正本，索引是影子

- 正文、设定、台账都是磁盘上的 Markdown / JSON，可以用任何编辑器打开，可以进 Git。
- 程序里的索引与缓存随时可以删掉重建，**不允许**成为第二个真相。
- 写入走「临时文件 → 原子改名 → Git 提交」，断电不会留下半个文件。

### 3. 记忆不等于上下文

一本百万字的书塞不进任何模型的上下文窗口。
所以我们不追求「一个 AI 记住全部」，而是：

- **设定档案**是持久数据（一张卡一个 JSON／一段 Markdown），永远存在；
- **档案负责人格**按需唤起（谁的相关就唤谁），任务结束就销毁；
- **共享黑板**记录谁在什么时候为哪一章改了什么，任何智能体都能精确检索它。

智能体共享的是「事实与日志」，不是「上下文窗口」。

## 为什么不用向量检索（RAG）

| | 精确检索 | 向量召回 |
|---|---|---|
| 回答 | 「林昭的左臂是什么时候废的」 | 「好像写过一场雨戏，在哪章」 |
| 特性 | 精确、可解释、零成本、不会串 | 能认出换了说法的同一件事 |

设定是**事实**，事实要唯一答案。用相似度去「猜」事实，漏召回一次就会写出「上一章已死的人又开口说话」。
所以：事实走档案卡 + 精确索引；向量只可能留给「模糊回忆」，且是后加的插件位。

## 模块都建齐了

当初规划的 `06 智能体运行时` / `09 台账同步` / `12 导出转换` 都已落地（见上表）；`08 正文写作` 后来没有单独建——执笔并进 `05 编排内核` 的提示词与 `01 应用外壳/请求处理.ts` 的续写 / 改写流程，单独开个空文件夹没有意义。

## 已知边界（诚实清单）

1. 台账由「同步台账」写回三册（时间线 / 出场追踪 / 承诺台账），其余四册仍只能手改。
2. 伏笔的「参考间隔 / 重要程度 / 意图」取自 `台账/承诺台账.md` 的可选列；没写参考间隔时不判超期，只按「搁置太久」（埋下 ≥ 15 章未兑）提醒。
3. 编辑器四态都能写能存，但落地仍是纯文本 Markdown：富文本是 contenteditable 上的显示层，没有引富文本编辑器库，也没有 diff。
4. 单机单库使用：书架只是本机打开过的路径清单；没有账号、云同步、协同。
5. **本机自动化会话里 Electron 窗口起不来**（进程秒退，连最小冒烟窗口都打不开），所以界面层靠浏览器预览（`npm run 预览` + 无头 Edge 截图）逐张看，而不是开着桌面窗口看。主进程、解析层、模型链路都已用无界面方式逐个验证通过。
6. 工具调用最多 4 轮；网关不认 `tools` 时退化成「约定 JSON 块」；写盘类工具永远等你回一句「确认」，没有全自动落盘。

## 一个必须记住的坑

这台机器的环境变量里有 `ELECTRON_RUN_AS_NODE=1`。带着它启动 Electron，程序会退化成纯 Node，窗口永远不出现，而且**没有任何报错**。
所以启动一律走 `启动.cmd`（它会先清掉这个变量）。

## 两种跑法，同一套代码

界面只有一份（`02 界面渲染`），业务只有一份（`01 应用外壳/请求处理.ts`）。外壳可以换：

| 跑法 | 入口 | 桥 | 用处 |
|---|---|---|---|
| 桌面应用 | `启动.cmd` → `99 构建产物/main.cjs` | `preload.cjs` 暴露的 `window.桥` | 日常写作，双击即开 |
| 浏览器预览 | `预览.cmd` → `99 构建产物/预览.cjs` | `02 界面渲染/网页桥.ts` 走 HTTP | 界面调试、外壳出问题时兜底、手机上也能看 |

两者的差别只在「怎么把请求递过去」：一个走 Electron IPC，一个走本地 HTTP（`127.0.0.1:5178`）。
AI 流式两边走的是同一段代码，只是一个用 `webContents.send` 推、一个用 SSE 推。

之所以要两条路：Electron 的 Chromium 在某些受限会话里起不来（本机自动化环境就是这样，进程秒退且不报错），
而界面本身没问题。有了浏览器这条，界面永远能被看到和被验证。

## 布局踩过的坑

CSS 里的类名是中文，很容易手滑写成 `主体 { }` 而不是 `.主体 { }` —— 前者会被当成「标签选择器」，
一个字符之差，整个三栏布局就退化成上下堆叠，而且浏览器一句错都不报。
同样的坑还有 `按钮`／`button`。**中文类名必须带点，元素选择器必须写真的标签名。**

## 台账同步（全自动直改）

保存一章后自动跑，也可以点「同步台账」手动跑。它会：

1. 让模型分两步读本章：先抽「谁在场／哪天／发生了什么」，再按 8 条一批判定「有没有真正兑现某条伏笔」（要求给出原文依据，给不出就算没兑现）。
2. 按章号写回三册台账：
   - `台账/时间线.md`：本章一行，重复同步先删旧行再插新行（幂等）
   - `台账/出场追踪.md`：在场者的「最后出场」刷到本章，出场记录补 `chN`
   - `台账/承诺台账.md`：判定兑现的伏笔，在「兑」列追加 `chN`（**原有计划文字保留，绝不覆盖**）
3. 三册一起进一个 Git 提交：`台账同步 ch27《背不回来》`，随时 `git revert` 撤销。
4. 每次同步写一条黑板事件（谁、哪章、改了什么、依据是什么）。

实测（ch27 副本）：时间线 +1 行 8 条事件、出场追踪 9 人刷新、承诺台账标记兑现，一次提交完成。

### 为什么分两次问

一开始把「抽事实 + 判伏笔」合成一个大提示词，推理模型会先把几百字规则反复咀嚼，8000 token 全烧在思考里，正文是空的——这不是模型不行，是**一次问太多**。
拆成短问句、每批只喂 8 条伏笔，同一模型 6 秒就给出干净 JSON。**窄问题比长规则可靠。**

### 一个安全规则

「兑」那一列原本写着作者的计划（`卷三抄本→卷十二→卷十八合账`）。程序只做**追加**，绝不会把计划改成一句 `ch27`——
自动化的边界是：可以加事实，不能删人的判断。

## 界面结构

```
┌─ 顶栏：书名 · 章数/字数/最新章 · 集群 14 人 ──── ☀日间 / 导出 / 设置 / 打开书库 ─┐
│ 左栏 220–460px   │ 中栏 自适应                     │ 右栏 320–640px          │
│ [章节][文件]     │ ch27 · 编辑 ｜ 全书视图         │ 模型 · ch27 · 用量累计  │
│ [台账][建议]     │ 源码│分屏│预览 + 语法工具栏      │ 对话 / 讨论 / 计划      │
│  四段切换         │ 或 仪表盘：进度 / 字数节奏 /    │ 气泡 / 工具回执         │
│ 卷→章 / 文件树 / │    伏笔甘特 / 人物 / 台账墙     │ 输入框 + 发送/停止      │
│ 伏笔看板 / 建议   │    （只读）                     │ 功能 ▾                  │
└──────────────────┴─────────────────────────────────┴─────────────────────────┘
```

- **左栏四段**：`章节`（卷→章目录）/ `文件`（书内文件树，点开即看，文本可改可存）/ `台账`（伏笔看板 + 七册）/ `建议`（派活后的待裁定条目，按章显示）。
- **三栏宽度可拖**：中栏两侧各一条分隔条，左栏 220–460px、右栏 320–640px，松手写进 `localStorage`，重开保持。
- **编辑器四态**：`富文本`（所见即所得，contenteditable）/ `源码`（纯文本框）/ `分屏`（左源码右预览，滚动按百分比同步）/ `预览`（整页 Markdown，只读）；四种都能 Ctrl+S，模式记在 `localStorage`，默认富文本。渲染与回写走 `02 界面渲染/编辑器渲染.ts`（`渲染Markdown` / `取回Markdown`），不引富文本编辑器库。
- **插入语法工具栏**：粗体 / 斜体 / 标题 / 引用 / 无序列表 / 有序列表 / 行内代码 / 分割线。有选中就包住，没选中插一对符号；行级语法再点一次是整段取消；改完把光标与选区放回去。
- **右栏气泡与用量**：每条消息一个气泡（`你` / `总编` / `改写` / `集群` / `系统`），悬停才露出复制 / 重试 / 重新生成；总编与改写的气泡底部是 `↑输入 ↓输出 · 缓存 xx%`，对话头是「本轮」累计。网关没给用量就显示「—」，不瞎算。
- **全书视图**：中栏顶部「编辑 ｜ 全书视图」切换（深链 `?视图=全书`，只影响这一次打开，不改存下来的偏好）。五块只读仪表盘——进度环（伏笔兑现率）、每章字数节奏、伏笔甘特、人物出场、台账墙；数据面板还能切**秘密矩阵**（读 `台账/知情台账.md`，按游标分「谁知道 / 谁知道到什么程度 / 依据哪句」与「谁还不知道」两栏）和**禁揭清单**（读 `情节/情节-03-禁揭清单.md`）。点左栏的章会切回编辑并打开那一章。
- **对话三模式**：`对话`（直接说）/ `讨论`（把议题抛给集群，成员接着说、总编收口）/ `计划`（让模型先拆再说）；模式键存在 `localStorage`。
- **对话过程卡布局参考 OpenFic（Apache-2.0），实现为本项目自写。

工具回执气泡**：模型每调一次工具，气泡里先落一条 `🔧 续写（{章节号:27}）→ 完成，23 字`；写盘工具显示「等你回一句『确认』」。工具冒烟结果不写进正文，只当上下文。
- **集群搬进设置**：顶栏「设置」弹窗有六个页签（`外观` / `编辑器` / `模型` / `上下文` / `智能体` / `书库`），集群在「智能体」里，左栏不再有集群页；弹窗外框固定 680px × min(660px, 84vh)，切页签只有内容区滚动。
- **AI 操作收进对话栏**：右栏输入框左边的「功能 ▾」决定这次发送做什么——`对话` / `续写` / `改写选中` / `同步台账` / `派活`；菜单右对齐、窗口一动就收起，不会飘到屏幕外；编辑器头部只剩「保存」。
- **明暗双主题**：顶栏右上角切换，写进 `localStorage`，重开保持；也可用 `?主题=亮` 直接指定。
- **滚动条**：统一 10px、圆角、底色透明，随主题换色（`--滚动条` / `--滚动条悬停`）。
- **配色**：所有颜色走 CSS 变量，暗色在 `:root`，亮色在 `[data-主题="亮"]`，切主题只换一组变量，组件代码一行不动。

## 工具调用（对话直接干活）

对话主循环在 `01 应用外壳/请求处理.ts`（`流式`），工具定义与守卫在 `06 智能体运行时/工具执行.ts`。

| 工具 | 中文名 | 写盘 |
|---|---|---|
| `continue_writing` | 续写 | — |
| `rewrite_passage` | 改写 | — |
| `sync_ledger` | 同步台账 | ✅ |
| `dispatch_cluster` | 派活 | ✅ |
| `read_file` | 读文件 | — |
| `query_ledger` | 查台账 | — |
| `query_setting` | 查设定 | — |
| `query_foreshadow` | 查伏笔 | — |
| `write_chapter` | 写章节 | ✅ |

- **最多 4 轮**：每轮把工具结果回灌再问；第 4 轮不再给 `tools`，逼它收口，收不了就明说「工具连了 4 轮还没收口，先停下」。
- **写盘确认闸**：写盘工具不确认就不执行。用户这一句里要有「确认 / 确定 / 批准 / 同意 / 执行 / 动手 / 就这样 / 开始吧 / 可以了 / 存吧 / 写吧 / 就这么办」之一；只回一句「同步台账」不算确认。
- **降级路径**：网关不认 `tools` 字段时，提示词里约定「输出 `\`\`\`json {"工具":"续写","参数":{…}} \`\`\``」，主进程用 `解析约定块` 抠出来照跑，结果以 user 消息回灌——能力不丢，只多一次往返。
- **只读投影**：`查台账 / 查设定 / 查伏笔` 不落任何文件，走 `06 智能体运行时/书库投影.ts` 的内存投影；伏笔那条和看板同一套算法，条数必然一致。
- **回执**：每次调用把 `工具回执`（名称 / 中文名 / 参数摘要 / 状态 / 轮次）推给右栏，成为气泡里那一行 🔧。

## Agent 集群

集群整体在「设置」→「智能体」页签里（左栏不再有集群页）。

### 成员怎么来的

打开书库时自动生成，存进 `数据目录/集群.json`（按书库路径分开，id 稳定）：

- **固定 6 位**：总编、审校、伏笔管家、台账员、地点负责人、物品负责人
- **人物负责人 N 位**：从 `台账/出场追踪.md` 的表里读人名，前 8 位各建一位
  本书实到 14 位：6 + 8（丸井三叶／双叶／一叶／千叶／佐藤信也…）

每位成员 = 一份人格 + 一份管辖清单（哪几个档案文件归它看）。

### 一次派活怎么跑

```
你点「准备第 28 章」
   → 选阵容：总编 + 伏笔 + 审校 + 人物负责人（默认 9 位）
   → 并发 4 路，每人一次模型调用
        · 装配上下文：自己的人格 + 自己管辖档案的前 1800 字
                     + 黑板里「其他智能体最近说过什么」（按关键词检索会话簿）
        · 产出结论，写进会话簿
   → 总编再跑一次，把 9 份回答合成「开写包」四段：
        【本章目标】【必须兑现】【不能写】【谁在场】
   → 结果落在右侧对话栏，可展开看每个人的原始回答
```

实测（第 27 章，9 位成员，13.5 秒全部返回）：

> 【本章目标】p-019 兑后余波——第 28 章优先接住 ch27 药箱已兑现后「箱侧条子无人签」的余波，不再另埋新扣。
> 【不写】不得新增伏笔；卷三 ch28–ch46 无正文无细纲，禁止擅自设定情节走向。
> 【谁在场】未定——须先查卷三前置包与第 28 章细纲。

注意三处 **「未定」**：档案里确实没有第 28 章的细纲，智能体没有编，这比编一个看起来像的答案有价值。

### 共享记忆怎么实现

- **会话簿**：`数据目录/会话/<书库指纹>.jsonl`，每次执行追加一条（谁、什么任务、产出、章节）。
- **互相可见**：任何成员装配上下文时，都会用任务关键词去会话簿里检索**其他成员**最近的记录，拼成「其他智能体最近的相关记录」。
  共享的是**事实与日志**，不是上下文窗口——所以 200 个设定也不会把上下文撑爆。
- 右侧对话栏的聊天记录存在 `localStorage`，重开还在。

### 还能做什么（下一步）

- 成员产出**直接落进档案**：现在把它抽成 `设定/待裁定/` 的条目等你拍板，不会自己改设定卡
- **建议一键采纳**：待裁定条目目前只记录，没有「应用」按钮，改不改由你动手
- **批量改稿**：一次对多章跑续写 / 改写，先出草稿再人审

## 收尾四件（2026-11-20）

### ① AI 分段流式写进编辑器

「AI 续写」的入口在右栏「功能 ▾ → 续写」（编辑器头部只剩「保存」）。行为不是「给一段文字让你复制」，而是**边生成边往正文里追加**：
每收到一个正文分片就 `set正文(旧 => 旧 + 分片)` 并标记未保存，还能随时「停止」。

- 提示词：`组装系统提示`（书名 + 本章 + 超期伏笔 + 正文尾部）再拼一段续写纪律：从断点往下、不复述、不解释、每段两个全角空格开头。
- 模型分工取「执笔」，温度 0.9，预算 8000 token。
- 推理模型会先想一会儿，这期间状态栏显示「模型在构思，马上落笔…」，不会让人以为卡死。

实测（第 27 章断点「天没亮。北门卸货区…」续 120 字）：

> 　　卸货区的铁皮顶被风掀开一角，垂下来半截，风一过就「啪嗒」敲一下，没人去管。地上还留着几道车辙，被踩乱了，看不出是往哪儿走。
> 　　最东那张桌子是搬不动才留下的，桌腿埋进水泥里。桌面上搁着一只搪瓷缸，缸底剩一指凉茶，旁边压着半张手写的清单，被水汽泡得起皱，最后一行没写完。

106 个正文分片，全角缩进、对话引号、物件细节都对得上原文。

### ② 派活结果落档案

每次派活结束自动追加到 `讨论/智能体派活.md`，并单独一个 Git 提交（`派活归档 ch27`）。
格式：时间 + 章节 + 任务 + 开写包 + 折叠的「各成员原始回答」。

放在**讨论区**是故意的：书库规矩写着「讨论/ 不许当依据」，
所以派活产出归档但不越权——它可以被追溯、被检索，但永远不会冒充台账。

实测副本：18 条进度事件、9 位成员、归档文件 32 行。

### ③ 智能体可改可删

集群里每位成员右边有「改」「删」。改 = 改名称 / 改职责（即人格）/ 改管辖文件；删 = 只从集群移除，**档案一个字节都不动**。
服务端两个通道：`集群/改`、`集群/删除`，都写回 `集群.json`，重启仍在。

实测：新建 → 16 人；改名 → 临时改名；删除 → 15 人，确认已移除。

### ④ 启动兜底

`启动.cmd` 现在调用 `18 构建工具/启动.ps1`：

```
清掉 ELECTRON_RUN_AS_NODE
 → 没构建过就先构建
 → 拉起 Electron，等 8 秒
 → 进程还活着：桌面窗口
 → 进程死了：自动起浏览器预览 + 打开 127.0.0.1:5178
```

这样即便某些环境下 Electron 起不来（我这台就是这样），双击桌面图标也一定能进到界面，不会出现「点了没反应」。
