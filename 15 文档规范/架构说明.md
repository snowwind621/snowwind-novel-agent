# 雪风小说工坊 · 架构说明

## 一句话

这是一个「以 AI 为主体」的长篇小说工作台：**事实在文件里，判断在智能体里，界面只负责让人随时能插手。**

## 三条铁律

### 1. 一个事实只存一处

正文只在 `manuscripts.binder/`；会随章节变的数据只在 `reference/台账/`；
稳定设定只在 `lorebook/` 与设定面板。别的文件提到它们时只写指针，不抄第二份。

这条不是形式主义：两份拷贝早晚改一边忘另一边，而长篇小说的崩坏都是从「同一个数字有两个版本」开始的。

### 2. 文件是正本，索引是影子

- 正文、设定、台账都是磁盘上的 Markdown / JSON，可以用任何编辑器打开，可以进 Git。
- 程序里的索引与缓存随时可以删掉重建，**不允许**成为第二个真相。
- 写入走「临时文件 → 原子改名 → Git 提交」，断电不会留下半个文件。

### 3. 记忆不等于上下文

一本百万字的书塞不进任何模型的上下文窗口。
所以我们不追求「一个 AI 记住全部」，而是：

- **设定档案**是持久数据（一张卡一个 JSON／一段 Markdown），永远存在；
- **档案负责人格**按需唤起（谁的相关就唤谁），任务结束就销毁；
- **共享黑板**记录谁在什么时候为哪一章改了什么，任何智能体都能精确检索它。

智能体共享的是「事实与日志」，不是「上下文窗口」。

## 为什么不用向量检索（RAG）

| | 精确检索 | 向量召回 |
|---|---|---|
| 回答 | 「林昭的左臂是什么时候废的」 | 「好像写过一场雨戏，在哪章」 |
| 特性 | 精确、可解释、零成本、不会串 | 能认出换了说法的同一件事 |

设定是**事实**，事实要唯一答案。用相似度去「猜」事实，漏召回一次就会写出「上一章已死的人又开口说话」。
所以：事实走档案卡 + 精确索引；向量只可能留给「模糊回忆」，且是后加的插件位。

```

  → 通道 ai/对话

  → 04 流式收字，把「思考」和「正文」分开推回界面
```

## 已知边界（诚实清单）

1. 现在只能**读**台账，还不能把 AI 的抽取结果**写回**台账表格。
2. 伏笔的超期判定用「参考间隔」，取自设定面板镜像里的 `参考间隔` 字段；镜像缺失时只按承诺台账判断。
3. 编辑器是朴素文本框，没有 diff、没有 Markdown 预览。
4. 多书库、子智能体、导出都还没做。
5. **本机自动化会话里 Electron 窗口起不来**（进程秒退，连最小冒烟窗口都打不开），所以界面层只做了静态构建与代码审查，没有跑起来看过。主进程、解析层、模型链路都已用无界面方式逐个验证通过。

## 一个必须记住的坑

这台机器的环境变量里有 `ELECTRON_RUN_AS_NODE=1`。带着它启动 Electron，程序会退化成纯 Node，窗口永远不出现，而且**没有任何报错**。
所以启动一律走 `启动.cmd`（它会先清掉这个变量）。

## 下一步（按价值排序）

1. **台账写回**：把 AI 抽取出的事实按「章号 + 条目」upsert 进 `reference/台账` 的表格行，写完立刻 Git 提交。这是「实时最新」的最后一公里。
2. **子智能体**：每个设定一个人格，按需唤起，读写共享黑板。
3. **导出**：TXT／Markdown／docx／EPUB。

## 两种跑法，同一套代码

界面只有一份（`02 界面渲染`），业务只有一份（`01 应用外壳/请求处理.ts`）。外壳可以换：

| 跑法 | 入口 | 桥 | 用处 |
|---|---|---|---|
| 桌面应用 | `启动.cmd` → `dist/main.cjs` | `preload.cjs` 暴露的 `window.桥` | 日常写作，双击即开 |
| 浏览器预览 | `预览.cmd` → `dist/预览.cjs` | `02 界面渲染/网页桥.ts` 走 HTTP | 界面调试、外壳出问题时兜底、手机上也能看 |

两者的差别只在「怎么把请求递过去」：一个走 Electron IPC，一个走本地 HTTP（`127.0.0.1:5178`）。
AI 流式两边走的是同一段代码，只是一个用 `webContents.send` 推、一个用 SSE 推。

之所以要两条路：Electron 的 Chromium 在某些受限会话里起不来（本机自动化环境就是这样，进程秒退且不报错），
而界面本身没问题。有了浏览器这条，界面永远能被看到和被验证。

## 布局踩过的坑

CSS 里的类名是中文，很容易手滑写成 `主体 { }` 而不是 `.主体 { }` —— 前者会被当成「标签选择器」，
一个字符之差，整个三栏布局就退化成上下堆叠，而且浏览器一句错都不报。
同样的坑还有 `按钮`／`button`。**中文类名必须带点，元素选择器必须写真的标签名。**

## 台账同步（全自动直改）

保存一章后自动跑，也可以点「同步台账」手动跑。它会：

1. 让模型分两步读本章：先抽「谁在场／哪天／发生了什么」，再按 8 条一批判定「有没有真正兑现某条伏笔」（要求给出原文依据，给不出就算没兑现）。
2. 按章号写回三册台账：
   - `设定-01-时间线`：本章一行，重复同步先删旧行再插新行（幂等）
   - `人物-01-出场追踪`：在场者的「最后出场」刷到本章，出场记录补 `chN`
   - `情节-01-承诺台账`：判定兑现的伏笔，在「兑」列追加 `chN`（**原有计划文字保留，绝不覆盖**）
3. 三册一起进一个 Git 提交：`台账同步 ch27《背不回来》`，随时 `git revert` 撤销。
4. 每次同步写一条黑板事件（谁、哪章、改了什么、依据是什么）。

实测（ch27 副本）：时间线 +1 行 8 条事件、出场追踪 9 人刷新、承诺台账标记兑现，一次提交完成。

### 为什么分两次问

一开始把「抽事实 + 判伏笔」合成一个大提示词，推理模型会先把几百字规则反复咀嚼，8000 token 全烧在思考里，正文是空的——这不是模型不行，是**一次问太多**。
拆成短问句、每批只喂 8 条伏笔，同一模型 6 秒就给出干净 JSON。**窄问题比长规则可靠。**

### 一个安全规则

「兑」那一列原本写着作者的计划（`卷三抄本→卷十二→卷十八合账`）。程序只做**追加**，绝不会把计划改成一句 `ch27`——
自动化的边界是：可以加事实，不能删人的判断。

- 左栏也支持 `?页=台账` 深链，方便截图与排查。

## Agent 集群

### 成员怎么来的

打开书库时自动生成，存进 `数据目录/集群.json`（按书库路径分开，id 稳定）：

- **固定 6 位**：总编、审校、伏笔管家、台账员、地点负责人、物品负责人
- **人物负责人 N 位**：从 `reference/台账/人物-01-出场追踪` 的表里读人名，前 8 位各建一位
  本书实到 14 位：6 + 8（丸井三叶／双叶／一叶／千叶／佐藤信也…）

每位成员 = 一份人格 + 一份管辖清单（哪几个档案文件归它看）。

### 一次派活怎么跑

```
你点「准备第 28 章」
   → 选阵容：总编 + 伏笔 + 审校 + 人物负责人（默认 9 位）
   → 并发 4 路，每人一次模型调用
        · 装配上下文：自己的人格 + 自己管辖档案的前 1800 字
                     + 黑板里「其他智能体最近说过什么」（按关键词检索会话簿）
        · 产出结论，写进会话簿
   → 总编再跑一次，把 9 份回答合成「开写包」四段：
        【本章目标】【必须兑现】【不能写】【谁在场】
   → 结果落在右侧对话栏，可展开看每个人的原始回答
```

实测（第 27 章，9 位成员，13.5 秒全部返回）：

> 【本章目标】p-019 兑后余波——第 28 章优先接住 ch27 药箱已兑现后「箱侧条子无人签」的余波，不再另埋新扣。
> 【不写】不得新增伏笔；卷三 ch28–ch46 无正文无细纲，禁止擅自设定情节走向。
> 【谁在场】未定——须先查卷三前置包与第 28 章细纲。

注意三处 **「未定」**：档案里确实没有第 28 章的细纲，智能体没有编，这比编一个看起来像的答案有价值。

### 共享记忆怎么实现

- **会话簿**：`数据目录/会话/<书库指纹>.jsonl`，每次执行追加一条（谁、什么任务、产出、章节）。
- **互相可见**：任何成员装配上下文时，都会用任务关键词去会话簿里检索**其他成员**最近的记录，拼成「其他智能体最近的相关记录」。
  共享的是**事实与日志**，不是上下文窗口——所以 200 个设定也不会把上下文撑爆。
- 右侧对话栏的聊天记录存在 `localStorage`，重开还在。

### 还能做什么（下一步）

- 成员可以**自己建**：现在阵容是自动生成的，还没做「新建自定义智能体」的入口
- 派活进度逐条推送（现在只有「正在召集…」一个状态）
- 成员产出可以**直接落进档案**（现在只写会话簿）

## 收尾四件（2026-11-20）

### ① AI 分段流式写进编辑器

编辑器头新增「AI 续写」。行为不是「给一段文字让你复制」，而是**边生成边往正文里追加**：
每收到一个正文分片就 `set正文(旧 => 旧 + 分片)` 并标记未保存，还能随时「停止」。

- 提示词：`组装系统提示`（书名 + 本章 + 超期伏笔 + 正文尾部）再拼一段续写纪律：从断点往下、不复述、不解释、每段两个全角空格开头。
- 模型分工取「执笔」，温度 0.9，预算 8000 token。
- 推理模型会先想一会儿，这期间状态栏显示「模型在构思，马上落笔…」，不会让人以为卡死。

实测（第 27 章断点「天没亮。北门卸货区…」续 120 字）：

> 　　卸货区的铁皮顶被风掀开一角，垂下来半截，风一过就「啪嗒」敲一下，没人去管。地上还留着几道车辙，被踩乱了，看不出是往哪儿走。
> 　　最东那张桌子是搬不动才留下的，桌腿埋进水泥里。桌面上搁着一只搪瓷缸，缸底剩一指凉茶，旁边压着半张手写的清单，被水汽泡得起皱，最后一行没写完。

### ② 派活结果落档案

每次派活结束自动追加到 `reference/讨论/讨论-智能体派活.md`，并单独一个 Git 提交（`派活归档 ch27`）。
格式：时间 + 章节 + 任务 + 开写包 + 折叠的「各成员原始回答」。

放在**讨论区**是故意的：你的 `reference/index.md` 写着「讨论/ 不许当依据，
所以派活产出归档但不越权——它可以被追溯、被检索，但永远不会冒充台账。

实测副本：18 条进度事件、9 位成员、归档文件 32 行。

### ③ 智能体可改可删

集群里每位成员右边有「改」「删」。改 = 改名称 / 改职责（即人格）/ 改管辖文件；删 = 只从集群移除，**档案一个字节都不动**。
服务端两个通道：`集群/改`、`集群/删除`，都写回 `集群.json`，重启仍在。

实测：新建 → 16 人；改名 → 临时改名；删除 → 15 人，确认已移除。

### ④ 启动兜底

`启动.cmd` 现在调用 `脚本/启动.ps1`：

```
清掉 ELECTRON_RUN_AS_NODE
 → 没构建过就先构建
 → 拉起 Electron，等 8 秒
 → 进程还活着：桌面窗口
 → 进程死了：自动起浏览器预览 + 打开 127.0.0.1:5178
```

这样即便某些环境下 Electron 起不来（我这台就是这样），双击桌面图标也一定能进到界面，不会出现「点了没反应」。
