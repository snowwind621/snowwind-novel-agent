# 目录规范

## 命名

- 顶层源码目录：`序号 + 空格 + 具体方向`，例如 `10 书库检索`。
- 序号只用一次，不复用，删掉一个模块后它的号就空着。
- `package.json` 的 `name`、代码里的标识符用英文（`setting-archive`、`library-index`），避免踩工具链的坑；**目录名**保持中文。
- 一个文件夹只能负责一个方向；一个代码文件只能负责一个功能。文件名就是它的职责说明书。

## 书写约束

- 每个源文件开头一行注释，写清「只负责一件事：……」。写不清，说明它该拆了。
- 跨模块只通过 `03 进程桥接/通道.ts` 的契约或明确的函数签名打交道，不靠全局变量。
- 不写「以后可能会用到」的参数与分支。

## 脚本目录（本工程的工具，不放业务）

`18 构建工具/` 只放构建与工具，**开发自检不许再长回这一层**：

| 文件 | 干什么 |
|---|---|
| `构建.mjs` | esbuild 打包主进程 / 预加载 / 浏览器预览 / 导入四个入口 |
| `整洁检查.mjs` | `npm run 整洁`：扫密钥、大文件、垃圾文件 |
| `回归检查.mjs` | `npm run 回归`：不联网、不调模型的回归自检 |
| `启动.ps1` · `上传.ps1` | 启动兜底、发布上传 |
| `校验书库.mjs` | `node "18 构建工具/校验书库.mjs" <书库目录> [--json] [--修复建议]`：按结构契约体检（表头 / 类型 / 章号 / 重复 / 断链 / 两处同事实） |
| `迁移-计划目录.mjs` | 目录归位时用的一次性迁移脚本，平时不跑 |

- **开发自检**（自检入口 / 主进程自检 / 写盘自检 / 台账自检 / 派活自检 / 联调入口）统一放 `18 构建工具/开发自检/`。
- **导入命令行**属于业务能力，放 `16 书库迁移/命令行导入.ts`，构建产出 `99 构建产物/导入.cjs`。

## 提交纪律

每次改动都走同一条流水线，不许跳步：

1. **先写更新日志**：在 `CHANGELOG.md` 的「未发布」里记一条，写清改了什么、为什么。
2. **再跑整洁检查**：`npm run 整洁`，五项全绿才继续。
3. **然后提交**：`.githooks/pre-commit` 会再扫一遍暂存内容，密钥/大文件/日志一律拦下。
4. **最后推送**：`git push`。

新增文件前先问三句：**它是正本还是产物？属于哪个序号目录？会不会泄漏密钥或个人路径？**
产物（`99 构建产物/`、日志、导出文件）一律进 `.gitignore`，不进库。

## 版本与发布纪律

**提交照常，发布要攒。** 每次改动都提交、都推送，但 GitHub Release 不跟着提交走。

- **什么算一次发布**：攒够一个完整主题（比如「改写循环 + 开写包 + 书架」这种一组能力），或者有破坏性变更。
- **版本号怎么走**：`0.x.y` —— `x` 只在有完整能力组或有破坏性变更时加一；`y` 留给修 bug 与打磨。
  **同一天内不连升版本**，更不许把版本号当计数器用。
- **发布动作**：把 CHANGELOG「未发布」整段搬到新版本号下 → 打 tag → 建 Release（标题与正文直接用那一段）。
- **不做的事**：每做一个功能就发一版；发了又删；为了显得活跃而发版。

日常提交的信息里写清楚改了什么就够了，版本号只对「使用者需要知道」的节点负责。

### 发布由谁决定

**由主代理裁决**（2026-11-20 起，用户授权）。**补丁优先**：日常改动攒进 `[未发布]`，发版时先发 `0.3.1`、`0.3.2` 这种补丁号；
次版本号只在真正的里程碑（换格式、换架构这种）才动，**同一天最多发一次，不许一天连跳两个次版本号**。

判据三条，满足两条就发：

1. **攒够一个主题**：至少三类改动凑成一个能一句话讲清的故事（例如「自有格式 + 打包 + 设置体系」）。
2. **有对外可见的变化**：用户双击 exe 或打开界面就能感知到，而不是纯内部重构。
3. **验证过关**：`npm run build`、`tsc --noEmit`、`npm run 回归`、`npm run 整洁` 全绿，且关键链路真机（或 CDP）走过。

每攒够一个版本，把 CHANGELOG 的 `[未发布]` 整段搬到新版本号下，打 tag，建 Release。**不发空版本，也不为了刷活跃发版。**

**两个例外，不是遗漏：**

- `node_modules/` 必须叫这个名字，npm 与 Node 的解析规则写死的，改成中文就装不上依赖。它已被 `.gitignore` 排除。
- `99 构建产物/` 用 99 是刻意的：它是**产物**不是源码，编号放最后，一眼能看出「这里可以整个删掉重来」。

其余所有源码目录一律「序号 + 空格 + 具体」，序号不复用、不跳号解释，删掉一个模块它的号就空着。
