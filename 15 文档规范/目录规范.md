# 目录规范

## 命名

- 顶层源码目录：`序号 + 空格 + 具体方向`，例如 `10 书库检索`。
- 序号只用一次，不复用，删掉一个模块后它的号就空着。
- `package.json` 的 `name`、代码里的标识符用英文（`setting-archive`、`library-index`），避免踩工具链的坑；**目录名**保持中文。
- 一个文件夹只能负责一个方向；一个代码文件只能负责一个功能。文件名就是它的职责说明书。

## 书写约束

- 每个源文件开头一行注释，写清「只负责一件事：……」。写不清，说明它该拆了。
- 跨模块只通过 `03 进程桥接/通道.ts` 的契约或明确的函数签名打交道，不靠全局变量。
- 不写「以后可能会用到」的参数与分支。

## 书库目录（被读取的项目，不是本工程）

```
<书库根>/
  project.yaml            书名等元信息
  AGENTS.md              本项目的写作纪律（给人和 AI 看）
  manuscripts.binder/    正文正本
    binder.xml           卷（group）→ 章（chapter id）
    000NN-章名.md        一章一个文件，编号即章号
  lorebook/              稳定设定（世界书），一条一个文件
    world/ character/ location/ item/ system/ event/ faction/ instruction/ note/
  reference/
    台账/                会随章节变的数据（唯一正本）
    情节/                承诺台账（伏笔）、细纲、禁揭清单
    核对/                校验与放行依据
    留痕/                历史口径（唯一允许写旧值的地方）
    考据/                原作考据，不作写作依据
    导航/                事实归属表
    设定面板-现状.json    设定面板镜像（含伏笔的参考间隔）
  manuscript/index.md    正文导航（不放正文）
```

## 提交纪律

每次改动都走同一条流水线，不许跳步：

1. **先写更新日志**：在 `CHANGELOG.md` 的「未发布」里记一条，写清改了什么、为什么。
2. **再跑整洁检查**：`npm run 整洁`，五项全绿才继续。
3. **然后提交**：`.githooks/pre-commit` 会再扫一遍暂存内容，密钥/大文件/日志一律拦下。
4. **最后推送**：`git push`。

新增文件前先问三句：**它是正本还是产物？属于哪个序号目录？会不会泄漏密钥或个人路径？**
产物（`dist/`、日志、导出文件）一律进 `.gitignore`，不进库。
