# 开发计划

> 这份文档回答四件事：**还差哪些功能**、**它们怎么互相配合**、**要调什么工具**、**开发者要准备什么环境**。
> 写在 2026-11-21，对应 `v0.1.3` 之后的代码状态。

---

## 一、这张地图怎么读

整个程序可以拆成四层，**依赖只能从上往下**（上层可以调下层，下层不许反向依赖）：

```
┌─ 交互层 ── 三栏界面 · 编辑器 · 数据面板 · 设置 · 对话栏
│
├─ 智能层 ── 模型接入 · 上下文装配 · 工具调用 · 集群调度 · 对话压缩
│
├─ 读写层 ── 文件工作区 · 书库检索 · 台账同步 · 导出转换 · 书库迁移
│
└─ 地基 ──── 书库格式（雪风卷宗 v1）· 单一事实来源 · Git 留痕 · 通道契约
```

**地基不稳，上面全塌。** 所以先看第一节的完成度，再谈还差什么。

### 半成品（必须收尾，否则不算完成）

| 欠账 | 为什么必须先做 | 大致工作量 |
|---|---|---|
| **设置里 11 项新参数只有 3 项生效** | 用户能在界面上改，但行为不变——这是「假开关」，比没有更糟 | 1–2 天 |
| **计划模式端到端没跑通** | 建计划 → 确认 → 逐步执行的链路只有代码，没在真实网关跑过 | 半天（跑通 + 修坑） |

| **知情台账只有表头** | 秘密矩阵现在只能显示空态 | 作者填，或 AI 辅助抽取 |
| **导出没有目录/分卷页码** | 长篇打印体验差 | 1 天 |

### 明确没做（要排进路线图）

- 自动更新（现在只能手动装新版）
- 代码签名（安装会提示「未知发布者」）
- 多书库同时打开（书架有，但同时只开一本）
- 向量召回 / 语义检索（当前刻意没有：事实需要权威值，不需要相似度）
- 多人协作

## 三、功能之间怎么配合

### 链路一：写作 → 落盘 → 留痕

```
编辑器输入
   ↓ 防抖（设置里的 0.5–5 秒）
写盘（原子写：先写临时文件再 rename，断电不损坏）  0.06 ms
   ↓
提交策略（11 文件工作区/提交策略.ts）
   ├─ 内容指纹没变 → 跳过
   ├─ 距上次 < 20 秒 → 只写盘，不提交
   └─ 到点 / Ctrl+S / 切标签 → git add + commit  约 140 ms
   ↓
台账同步（可选，走工具调用）→ 事实抽取 → 表格改写 → 看板刷新 → 数据面板
```

**关键设计**：写盘贵不贵不在意，**git 才是贵的**。所以两者分开节流，并且手动保存永远立即提交。

### 链路二：对话 → 工具 → 事实

```
用户一句话
   ↓ 选模式（对话 / 讨论 / 计划）
工具集过滤（讨论=只读 5 个；计划=只读 + 建计划；对话=全部 13 个）
   ↓
模型返回 tool_calls（或降级成 ```json 约定块）
   ↓
工具执行（06 智能体运行时/工具执行.ts）
   ├─ 只读工具 → 走「只读投影」（内存现算，不落盘）
   └─ 写盘工具 → 先要「确认」，作者没说确认就停下
   ↓
结果回灌给模型 → 模型收口 → 界面显示工具气泡 + 真相
```

**关键设计**：agent 查事实不靠正则抠表格，靠 `书库投影.ts` 把 Markdown 现算成结构化 JSON。**磁盘上永远只有一份文件。**

### 链路三：计划 → 确认 → 执行

```
计划模式提问
   ↓
模型调 `建计划` → 写 `计划/计划表/<日期> <标题>.md`（步骤表，末列「执行结果」留空）
   ↓ 本轮结束，界面显示计划卡（确认执行 / 先不做）
作者点确认
   ↓
服务端逐步执行（白名单：续写/同步台账/派活/读文件/查台账/查设定/查伏笔/查知情）
   ↓ 每步结果写回计划表「执行结果」列并提交
最后一条总结
```

**为什么执行放在服务端而不是让模型自己调**：模型可能把一句「写整章」当成步骤自动覆盖正文；白名单保证只有可逆、可解释的动作会被执行。

### 链路四：事实 → 界面

```
Markdown 正本（唯一事实来源）
   ├─→ 解析器（台账解析 / 项目扫描）→ 看板 → 数据面板（人看）
   └─→ 只读投影（内存现算）→ agent 查询（机器看）
```

### 依赖方向的红线

| 允许 | 禁止 |
|---|---|
| `01 应用外壳` 调 `05/06/09/10/12` | `10 书库检索` 反向依赖问 `02 界面渲染` |
| `02 界面渲染` 只通过 `桥` 调用后端 | 界面直接读磁盘文件 |
| 任何模块调 `11 文件工作区` 写盘 | 各模块自己 `fs.writeFile` |
| 任何模块从 `10 书库检索/书库布局.ts` 取路径 | 硬编码 `"台账/时间线.md"` 这种字符串 |

## 四、还差的功能：按依赖排序

顺序不是按重要性，是**按「不做完这个，后面的做了也要返工」**。

### 第 1 批：把假开关变成真开关（P0）

| 设置项 | 谁该读它 |
|---|---|
| 编辑器.自动Git | `11 文件工作区/提交策略.ts`（关掉就只写盘） |
| 编辑器.撤回栈深度 | `02 界面渲染/正文编辑.tsx`（现在写死 100） |
| 模型.失败换模型 | `04 模型接入/网关客户端.ts`（重试时换下一个分工模型） |
| 模型.最大工具轮 | `01 应用外壳/请求处理.ts`（现在写死 4） |
| 上下文.摘要模型 / 注入上章 | `06 智能体运行时/对话压缩.ts`、`上下文装配.ts` |
| 书库.校验修复建议 / 导出格式 | `18 构建工具/校验书库.mjs`、`12 导出转换/` |

**验收标准**：改一项 → 行为真的变，且能用日志证明它读到了这个值。

### 第 2 批：AI 链路收口（P0）

1. **计划模式端到端**：假网关 + 真实网关各跑一次，覆盖「不确认不执行」「确认后逐步执行」「中途失败」三种情况。
2. **讨论挪服务端**：新增 `集群/讨论` SSE 通道，复用 `05 编排内核` 的并发池，结果归档进 `讨论/`。
3. **工具结果可见性**：工具气泡已有，补「点开看完整结果」。

### 第 3 批：写作体验（P1）

- 编辑器精确行定位（给富文本块加 `data-行号`，出处跳转按行滚）。
- 大章节性能（十万字切模式卡顿，考虑分块渲染）。
- 导出：目录页码、分卷封页、docx 页眉。

### 第 4 批：交付形态（P1）

- 代码签名（或至少写清「未知发布者」怎么绕过）。
- 自动更新（electron-updater + `latest.yml` 已经在产出）。
- 首次启动引导（选书库 / 配网关）。

### 第 5 批：往后再说（P2）

- 多书库并行、团队协作、移动端、语义检索。

## 五、要用哪些工具（技术栈）

| 层 | 工具 | 干什么 | 为什么不选别的 |
|---|---|---|---|
| 运行时 | **Node.js 20+** | 主进程、脚本、构建 | Electron 33 自带，够用 |
| 桌面壳 | **Electron 33** | 窗口、文件、菜单 | Tauri 要 Rust 工具链，团队不熟 |
| 界面 | **React 18 + Vite 5** | 三栏界面 | 生态最稳，热更新好用 |
| 打包 | **esbuild** | 主进程/预加载/脚本 → CJS | 比 webpack 快一个量级 |
| 安装包 | **electron-builder（NSIS）** | 出安装版 exe | 不用自己写 NSIS 脚本 |
| 数据 | **纯文件（Markdown + YAML frontmatter）** | 书库 | 用 SQLite 会有「库和文件不一致」，见铁律 |
| 版本 | **Git**（书库本身就是仓库） | 每次写入可回滚 | 自带、无需服务端 |
| 校验 | **自写 `书库校验.ts`** | 结构体检 | 通用校验器不懂我们的业务契约 |
| 测试 | **自写回归脚本（31 条）** | 离线验证 | 不引 Jest：要跑得快、不联网、依赖少 |
| 渲染 | **自写 Markdown 渲染器 / 手绘 SVG** | 编辑器预览、图表 | 引库会带来体积与安全面（`dangerouslySetInnerHTML` 只喂自产 HTML） |
| 图标 | **Lucide（ISC，只内联 path）** | 界面图标 | 零运行时依赖，颜色跟随 currentColor |
| 模型 | **OpenAI 兼容网关** | 生成 | 用户已有网关，换模型不用改代码 |
| 验收 | **headless Edge/Chrome + CDP** | 真点真拖真截图 | Electron 在无桌面环境起不来，浏览器预览跑同一份后端 |

**刻意不引入的**：状态管理库（React 自带 state 够）、UI 组件库（视觉要统一自己写）、ORM、i18n 框架、CSS-in-JS。

## 六、开发者要准备什么

### 6.1 环境（一次装好）

| 需要 | 版本 | 怎么装 / 怎么验 |
|---|---|---|
| Node.js | **20 LTS 或 22** | `node -v`；npm 随装 |
| Git | 任意近两年版本 | `git --version`，并配 `user.name` / `user.email` |
| 编辑器 | VS Code | 推荐插件：ESLint、Prettier、Chinese (Simplified) Language Pack |
| 浏览器 | Edge 或 Chrome | 用于预览与 CDP 验收 |
| 磁盘 | ≥ 2 GB 空闲 | `node_modules` 约 600 MB，安装包 79 MB |

### 6.2 第一次跑起来（约 5 分钟）

```bash
git clone https://github.com/snowwind621/snowwind-novel-agent.git
cd snowwind-novel-agent
npm install                      # 装依赖（含 electron、electron-builder）
npm run build                    # 构建四个入口到 99 构建产物/
npm run 预览                      # 起浏览器预览：http://127.0.0.1:5178
```

想跑真正的桌面窗口（需要桌面会话）：

```bash
npm start        # 或双击 启动.cmd
```

> ⚠️ **Windows 上如果窗口不出现**：检查环境变量 `ELECTRON_RUN_AS_NODE`，它会让 Electron 退化成 Node，什么都不显示。`启动.cmd` 已经会清掉它。

### 6.3 要配的东西

| 配置 | 在哪 | 说明 |
|---|---|---|
| 网关地址 / 密钥 / 模型 | 软件内「设置 → 模型」 | 或直接改 `%APPDATA%\snowwind-novel-agent\设置.json` |
| 书库位置 | 「设置 → 书库」或 `--书库=<路径>` | 默认放 `文档/雪风卷宗/` |
| 打包镜像（国内） | 环境变量 `ELECTRON_BUILDER_BINARIES_MIRROR` | 不设会去 GitHub 下 NSIS，容易 EOF |

### 6.4 日常命令

```bash
npm run build      # 构建（改完代码必跑）
npm run 预览        # 浏览器预览（不会自动热更新，改完要重新 build + 刷新）
npm run 预览:重启    # 端口被占 / 构建换哈希导致白屏时用这个
npm run 回归        # 31 条离线自检，几毫秒跑完
npm run 整洁        # 密钥 / 大文件 / 垃圾文件检查（提交钩子会跑）
npm run 校验书库 -- <书库目录>   # 书库结构体检
npm run 打包        # 出安装版 exe
```

## 七、怎么验证（不写测试会返工）

三层，缺一不可：

| 层 | 手段 | 跑多久 | 抓什么 |
|---|---|---|---|
| 类型 | `npx tsc --noEmit` | 3 秒 | 接口对不上、字段拼错 |
| 逻辑 | `npm run 回归`（31 条） | 10 毫秒 | 解析、命名、伏笔状态机、表格改写 |
| 界面 | headless 浏览器 + CDP 真点 | 1 分钟 | 布局错位、点不到、白屏 |

**造测试数据的两个工具**（都在 `18 构建工具/开发自检/`）：

- **假网关**：在本机 3077 端口起一个 OpenAI 兼容服务，能吐固定回复、能吐 `tool_calls` 分片、能按需报 500 或超时。**别打用户真实网关**。
- **样本书库**：回归脚本会自己造一个最小书库（`99 构建产物/回归样本/`），跑完可删。

**界面验收的固定套路**：

```bash
npm run build && npm run 预览:重启
/c/Program\ Files\ (x86)/Microsoft/Edge/Application/msedge.exe \
  --headless=new --disable-gpu --hide-scrollbars \
  --virtual-time-budget=8000 --window-size=1600,1000 \
  --screenshot=99构建产物/check.png http://127.0.0.1:5178/
```

要交互（点按钮、拖分隔条、输入文字）就得用 CDP：Page.enable + Runtime.evaluate 里 `element.click()`，比装 Puppeteer 轻。

## 八、发布流程

```
改代码 → 补 CHANGELOG「未发布」→ npm run build / 回归 / 整洁 → 提交 → push
                                                              ↓
                                    攒够一个主题 → 发补丁版（0.1.4）
                                                              ↓
                      改 package.json version → npm run 打包 → git tag → push tag → 建 Release
```

**节奏规矩**（写在 `目录规范.md` 里）：

- 日常改动进 `[未发布]`；发版先发补丁号；**次版本号只在真里程碑动**。
- 同一天最多发一次，不许一天连跳两个次版本号。
- 已发布的 Release 不删不改。

## 九、协作规则（多人 / 多 agent）

| 规矩 | 为什么 |
|---|---|
| 每个任务声明**写域**（能改哪些文件） | 两个 agent 改同一个文件必然互相覆盖 |
| 有依赖的任务用 `blocked_by` 排队 | 比如「设置界面」要等「设置字段」先定 |
| 长文件**禁止「读取限行 + 整文件写回」** | 我们已经被这个坑过两次：CHANGELOG 从 139 行截成 37 行、样式.css 从 993 行截成 749 行 |
| 提交前跑 `npm run 整洁` | 防密钥泄漏、防日志文件、防大文件 |
| 功能改动必须补 CHANGELOG | 否则半年后没人知道为什么这么写 |

## 十、已经踩过的坑（省下你的调试时间）

| 现象 | 原因 | 解法 |
|---|---|---|
| Electron 窗口不出现、也没报错 | `ELECTRON_RUN_AS_NODE=1` | 启动前清掉该变量 |
| 页面白屏、无报错 | 构建换了哈希，浏览器缓存了旧 HTML | 预览服务已加 `no-store`；应急用 `?清缓存=1` |
| 每保存一次弹一堆黑窗口 | `git` 子进程没加 `windowsHide` | 已在 `Git提交.ts` 修 |
| 打包报 `Access is denied` / `EOF` | 去 GitHub 下 Electron / NSIS | 配 `electronDist` 复用本机 + 用镜像 |
| `fs.cpSync` 直接崩（退出码 0xC0000409） | Node 24 / Windows 的坑 | 用自写递归拷贝 |
| 模型返回空正文 | 推理模型的思考吃光 token | 放宽 max_tokens、提示词写窄 |
| 端口 5178 被占，新服务起不来 | 旧进程没退 | `npm run 预览:重启` |
| 引用别人项目的代码 | 例如 nb-story 是 **AGPL-3.0** | 只借鉴设计，代码自己写 |
