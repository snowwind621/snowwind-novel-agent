# 打包说明

## 一句话

`npm run 打包`，等一两分钟，`dist/发布/雪风小说工坊-0.2.0-便携版.exe` 就是成品：**双击运行，不用安装，不写注册表**。

## 怎么打

```bash
npm install     # 首次：装依赖，electron-builder 在 devDependencies 里
npm run 打包    # 构建 + 打包，一条命令到底
```

`npm run 打包` 内部只有两步，顺序固定：

1. `npm run build` —— vite 出界面产物，esbuild 出 `dist/main.cjs` 与 `dist/preload.cjs`；
2. `node 打包/打便携exe.mjs` —— 用 `打包/打包配置.yml` 驱动 electron-builder 产出便携 exe，
   最后在控制台打印产物**绝对路径与体积**。

`打包/` 里就两个文件，目录内不再分子目录：

| 文件 | 干什么 |
|---|---|
| `打包/打包配置.yml` | electron-builder 配置：打包范围、asar、便携目标 |
| `打包/打便携exe.mjs` | 调 electron-builder，收尾报出产物路径与体积 |

## 产物在哪

- 成品：`dist/发布/雪风小说工坊-0.2.0-便携版.exe` —— **71.3 MB**
- 解包目录：`dist/发布/win-unpacked/`，里面的 `雪风小说工坊.exe` 可以直接双击（调试用，别拿去分发）

`dist/` 已在 `.gitignore` 里，产物不进库。下载缓存与临时文件也都在 `dist/eb-cache`、`dist/tmp` 里，
删 `dist/` 就是彻底清干净。

## 打包范围

`app.asar` 里只有：

```
package.json
dist/main.cjs
dist/preload.cjs
dist/renderer/**
node_modules/{react,react-dom,scheduler}    ← production 依赖，electron-builder 自动带
```

`dist/` 里还躺着截图、`预览.cjs`、`派活自检.cjs`、建 Release 的脚本——统统不进包，
所以配置里写的是三条具体路径，**不要**图省事改成 `dist/**`，那会白胖几十兆。

devDependencies（electron、vite、typescript、electron-builder、esbuild、@types/*）一个都不带，
这是 electron-builder 的默认行为，不需要额外配置。

## 为什么不签名

1. **没有证书。** 代码签名证书按年买（OV 几千、EV 上万），这是个人项目，不出这笔钱。
2. **签了也不等于「免杀」。** SmartScreen 认的是**签名信誉**，不是签没签。新证书首发照样弹
   「Windows 已保护你的电脑」，得靠下载量与时间慢慢养信誉。
3. **便携版的定位就是给自己人和同好用。** 分发时写明「更多信息 → 仍要运行」这一步，
   比花几千块买一张照样弹窗的证书实在。

哪天真要发给陌生人用，按这个顺序办：买 OV 证书 → 配 `CSC_LINK` 与 `CSC_KEY_PASSWORD` 环境变量 →
把 `打包配置.yml` 里 `win.signAndEditExecutable` 改回 `true` → 同一份配置自动签名，脚本不用改。

> `signAndEditExecutable: false` 是当前默认值。它关掉的是「用 rcedit 改写 exe 内部图标与版本资源」，
> 因为 rcedit 来自 winCodeSign 包，那个包里带 macOS 的符号链接，Windows 没开「开发者模式」时
> 7z 解不开（要管理员权限）。便携 exe 自己的版本信息由 NSIS 写入，不受这项影响。

## 命令行参数

打包后的 exe 和 `npm start` 行为一致，支持指定书库：

```bat
雪风小说工坊-0.2.0-便携版.exe --书库="D:\我的书库"
雪风小说工坊-0.2.0-便携版.exe --书库 "D:\我的书库"
```

两种写法都认（`--书库=路径` 与 `--书库 路径`），不传就照旧弹目录选择框。
这段解析在 `01 应用外壳/主进程.ts` 的 `命令行书库()` 里，打包后依然生效（代码原样进了 `app.asar`）。

## 数据落在哪

便携 exe 运行时把自己解到临时目录，所以**设置不能放在 exe 旁边**。程序按 Electron 惯例存到：

```
%APPDATA%\snowwind-novel-agent\     ← 设置.json、诊断.log
```

卸载 = 删 exe（+ 上面这个目录）。书库本身是你自己的文件夹，跟 exe 没关系，拷到新机器照样接着写。

## 启动.cmd 没动

`启动.cmd` 走 `脚本/启动.ps1`：优先拉桌面外壳，拉不起来退回浏览器预览。
这条兜底逻辑一行没改——改完源码想立刻看效果还是双击 `启动.cmd`；
便携 exe 只服务于「拷给别人 / 对方不想装 Node」的场景。

## 出问题先看这

| 现象 | 原因与处置 |
|---|---|
| 报 `没找到 electron-builder` | `npm install` 没跑，或依赖目录被裁过 |
| 卡在 `downloading` | 首次要下 NSIS 工具（几 MB，走 GitHub）。墙内不通就设镜像：`set ELECTRON_BUILDER_BINARIES_MIRROR=https://registry.npmmirror.com/-/binary/electron-builder-binaries/` |
| `makensis … error creating mmap` | 系统临时目录被限权/空间不足。脚本已把 `TMP/TEMP` 指到 `dist/tmp`，若仍报，检查磁盘剩余空间 |
| `open …electron-v33…zip: Access is denied` | electron-builder 想重下 115 MB 的 Electron。配置里 `electronDist: node_modules/electron/dist` 直接复用已装好的，不联网 |
| exe 打不开、白屏 | 先看 `%APPDATA%\snowwind-novel-agent\诊断.log`，再确认 `dist/renderer/**` 有没有漏进包 |
