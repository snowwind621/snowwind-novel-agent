# 打包说明

## 一句话

`npm run 打包`，等一两分钟，`99 构建产物/发布/雪风小说工坊-0.1.3-安装版.exe` 就是成品：**78.8 MB，双击安装，可选安装目录，自动建开始菜单与桌面快捷方式**。

> 从这一版起不再出便携版（免安装 exe）。要「拷给别人直接跑」的场景已经没有了——安装包更规整：快捷方式、卸载项、版本信息都由 NSIS 管。

## 怎么打

```bash
npm install     # 首次：装依赖，electron-builder 在 devDependencies 里
npm run 打包    # 构建 + 打包，一条命令到底
```

`npm run 打包` 内部只有两步，顺序固定：

1. `npm run build` —— vite 出界面产物，esbuild 出 `99 构建产物/main.cjs` 与 `99 构建产物/preload.cjs`；
2. `node "19 打包发布/打安装包.mjs"` —— 用 `19 打包发布/打包配置.yml` 驱动 electron-builder 产出 NSIS 安装包，
   最后在控制台打印**每个 exe 的绝对路径与体积**。

`19 打包发布/` 里就两个文件，目录内不再分子目录：

| 文件 | 干什么 |
|---|---|
| `19 打包发布/打包配置.yml` | electron-builder 配置：打包范围、asar、NSIS 安装行为 |
| `19 打包发布/打安装包.mjs` | 调 electron-builder，收尾报出产物路径与体积 |

## 产物在哪

- 成品：`99 构建产物/发布/雪风小说工坊-0.1.3-安装版.exe` —— **78.8 MB**（文件名里的版本号取自 `package.json`）
- 同名 `.exe.blockmap` 与 `latest.yml`：自动更新用的元数据，见下面「自动更新」一节——**这两个文件要和 exe 一起上传**，少一个客户端就查不到更新
- 解包目录：`99 构建产物/发布/win-unpacked/`，里面的 `雪风小说工坊.exe` 可以直接双击（调试用，别拿去分发）

`99 构建产物/` 已在 `.gitignore` 里，产物不进库。下载缓存与临时文件也都在 `99 构建产物/eb-cache`、`99 构建产物/tmp` 里，
删 `99 构建产物/` 就是彻底清干净（下次打包会重下 NSIS 工具）。

## 装完是什么样

配置写在 `打包配置.yml` 的 `nsis:` 段，行为逐条都能对照：

| 配置 | 值 | 装的时候看到什么 |
|---|---|---|
| `oneClick` | `false` | 走向导，不是一键装完；有「下一步」 |
| `perMachine` | `false` | 装到当前用户，**不需要管理员权限**，也不写 `Program Files` |
| `allowToChangeInstallationDirectory` | `true` | 安装目录可选 |
| `createStartMenuShortcut` / `createDesktopShortcut` | `true` | 开始菜单与桌面各一个「雪风小说工坊」 |
| `shortcutName` | `雪风小说工坊` | 快捷方式名 |
| `deleteAppDataOnUninstall` | `false` | 卸载**不删** `%APPDATA%\snowwind-novel-agent`（设置还在，重装接着用） |
| `artifactName` | `雪风小说工坊-${version}-安装版.${ext}` | 产物文件名 |

## 打包范围

`app.asar` 里只有：

```
package.json
99 构建产物/main.cjs
99 构建产物/preload.cjs
99 构建产物/renderer/**
node_modules/{react,react-dom,scheduler}    ← production 依赖，electron-builder 自动带
```

`99 构建产物/` 里还躺着截图、`预览.cjs`、自检脚本、建 Release 的脚本——统统不进包，
所以配置里写的是三条具体路径，**不要**图省事改成 `99 构建产物/**`，那会白胖几十兆。

devDependencies（electron、vite、typescript、electron-builder、esbuild、@types/*）一个都不带，
这是 electron-builder 的默认行为，不需要额外配置。

> 现在的 exe 图标还是 Electron 默认图标（打包日志会打一行 `default Electron icon is used`），
> 因为图标资源要从 rcedit 那条路走，见下一节。要换图标得先解决那件事。

## 为什么不签名

1. **没有证书。** 代码签名证书按年买（OV 几千、EV 上万），这是个人项目，不出这笔钱。
2. **签了也不等于「免杀」。** SmartScreen 认的是**签名信誉**，不是签没签。新证书首发照样弹
   「Windows 已保护你的电脑」，得靠下载量与时间慢慢养信誉。
3. **定位就是给自己人和同好用。** 分发时写明「更多信息 → 仍要运行」这一步，
   比花几千块买一张照样弹窗的证书实在。

哪天真要发给陌生人用，按这个顺序办：买 OV 证书 → 配 `CSC_LINK` 与 `CSC_KEY_PASSWORD` 环境变量 →
把 `打包配置.yml` 里 `win.signAndEditExecutable` 改回 `true` → 同一份配置自动签名，脚本不用改。

> `signAndEditExecutable: false` 是当前默认值。它关掉的是「用 rcedit 改写 exe 内部图标与版本资源」，
> 因为 rcedit 来自 winCodeSign 包，那个包里带 macOS 的符号链接，Windows 没开「开发者模式」时
> 7z 解不开（要管理员权限）。安装包的版本信息由 NSIS 写入，不受这项影响。

## 命令行参数

装好之后，程序本身和 `npm start` 行为一致，支持指定书库；`.exe` 换成安装目录里的那个即可：

```bat
"%LOCALAPPDATA%\Programs\雪风小说工坊\雪风小说工坊.exe" --书库="D:\我的书库"
雪风小说工坊.exe --书库 "D:\我的书库"
```

两种写法都认（`--书库=路径` 与 `--书库 路径`），不传就照旧弹目录选择框。
这段解析在 `01 应用外壳/主进程.ts` 的 `命令行书库()` 里，打包后依然生效（代码原样进了 `app.asar`）。

## 数据落在哪

安装的是程序，**书库和设置都不在安装目录里**。程序按 Electron 惯例存到：

```
%APPDATA%\snowwind-novel-agent\     ← 设置.json、诊断.log、集群.json、书架.json、会话/
```

- **卸载不删这个目录**（`deleteAppDataOnUninstall: false`），重装后设置与集群还在。
- 想彻底清干净：卸载后再手动删 `%APPDATA%\snowwind-novel-agent`。
- 书库本身是你自己的文件夹，跟安装目录没关系，拷到新机器照样接着写。

## 启动.cmd 没动

`启动.cmd` 走 `18 构建工具/启动.ps1`：优先拉桌面外壳，拉不起来退回浏览器预览。
这条兜底逻辑一行没改——改完源码想立刻看效果还是双击 `启动.cmd`；
安装包只服务于「给自己 / 给同好装一台机器」的场景。

## 出问题先看这

| 现象 | 原因与处置 |
|---|---|
| 报 `没找到 electron-builder` | `npm install` 没跑，或依赖目录被裁过 |
| 卡在 `downloading` | 首次要下 NSIS 工具（几 MB，走 GitHub）。墙内不通就设镜像：`set ELECTRON_BUILDER_BINARIES_MIRROR=https://registry.npmmirror.com/-/binary/electron-builder-binaries/` |
| `makensis … error creating mmap` | 系统临时目录被限权/空间不足。脚本已把 `TMP/TEMP` 指到 `99 构建产物/tmp`，若仍报，检查磁盘剩余空间 |
| `open …electron-v33…zip: Access is denied` | electron-builder 想重下 115 MB 的 Electron。配置里 `electronDist: node_modules/electron/dist` 直接复用已装好的，不联网 |
| 安装时提示「未知发布者」 | 没签名，属预期。点「更多信息 → 仍要运行」 |
| 装完图标是 Electron 默认图标 | `signAndEditExecutable: false` 时 rcedit 不跑，NSIS 只写版本信息；要换图标先解决 winCodeSign 解包那条路 |
| 装了打不开、白屏 | 先看 `%APPDATA%\snowwind-novel-agent\诊断.log`，再确认 `99 构建产物/renderer/**` 有没有漏进包 |

## 自动更新（electron-updater）

主进程侧模块：`19 打包发布/自动更新.cjs`；更新源写在 `打包配置.yml` 的 `publish:` 段（generic，一个静态目录就够）。

**一次发布要上传三个文件**（都在 `99 构建产物/发布/`）：

```
雪风小说工坊-<版本>-安装版.exe
雪风小说工坊-<版本>-安装版.exe.blockmap
latest.yml            ← 客户端先读它比对版本，再决定下不下
```

把 `publish.url` 指向存放这三个文件的目录即可。**换版本只改 `package.json` 的 `version`**，其余照旧 `npm run 打包`。

客户端行为（有意克制）：

| 情况 | 表现 |
|---|---|
| 启动 8 秒后第一次检查，之后每 6 小时一次 | 后台进行，界面不打扰 |
| 没有网络 / 连不上源 | 静默，只在状态通道里留一句「连不上更新源」 |
| 没有新版本 | 静默 |
| 有新版本 | **后台自动下载**（`autoDownload = true`），不打断写作 |
| 下载完成 | 推 `更新/就绪`，下次退出时自动安装（`autoInstallOnAppQuit = true`） |
| 开发环境（`electron .` 直接跑） | 直接跳过 |

**接线（属于 `01 应用外壳/`，不在本任务的写域，需要主进程负责人补）**：

```ts
const { 初始化自动更新 } = require("../19 打包发布/自动更新.cjs")
app.whenReady().then(() => {
  初始化自动更新({ 取窗口: () => 主窗口, 开发中: !app.isPackaged })
})
```

预加载（可选，不接也能更新，只是界面看不到提示）：

```ts
ipcRenderer.on("更新/状态", (_事件, 载荷) => 回调(载荷))
ipcRenderer.on("更新/就绪", (_事件, 载荷) => 回调({ ...载荷, 阶段: "就绪" }))
```

没装 `electron-updater` 时模块会**静默降级**（`初始化自动更新()` 返回 `{ 可用: false }`），所以 `npm i electron-updater` 之前打包也不会炸。

## 代码签名：未签名时用户看到什么

安装包**没有代码签名**（`打包配置.yml` 里 `signAndEditExecutable: false`）。用户第一次运行会撞上三处提示，都不是病毒，是 Windows 不认识这个发布者：

| 位置 | 用户看到的 | 绕过办法 |
|---|---|---|
| 双击安装包 | SmartScreen 蓝屏「Windows 已保护你的电脑」，下方写「未知发布者」 | 点 **更多信息** → **仍要运行** |
| 安装过程 | UAC 里发布者显示「未知」 | 装的是当前用户（`perMachine: false`），多数机器不弹 UAC；弹了点「是」 |
| 首次启动 | SmartScreen 再挡一次 exe | 「更多信息 → 仍要运行」；这台机器之后不再问 |
| 少数杀软 | 报「可疑文件 / 未签名程序」 | 把安装目录加白名单；先下载到本地再装，别在压缩包里直接运行 |

随包给用户看的简版说明：`19 打包发布/安装说明.md`（打包后可以连同 exe 一起发出去）。

## 自签名证书值不值得做（结论：不值得，先不做）

技术上能做：PowerShell 生成自签证书，`signtool` 签 exe。

```powershell
# 1) 生成（当前用户，代码签名用途，3 年）
$c = New-SelfSignedCertificate -Type CodeSigningCert -Subject "CN=雪风" -CertStoreLocation Cert:\CurrentUser\My -NotAfter (Get-Date).AddYears(3)
# 2) 导出（给别的机器装时要先把这个 pfx 导入「受信任的发布者」）
Export-PfxCertificate -Cert $c -FilePath 雪风自签.pfx -Password (Read-Host -AsSecureString)
# 3) 签名（signtool 来自 Windows SDK）
signtool sign /f 雪风自签.pfx /fd SHA256 /tr http://timestamp.digicert.com /td SHA256 雪风小说工坊-<版本>-安装版.exe
```

为什么不做：

1. **SmartScreen 照样拦**。它的信誉来自证书颁发机构 + 下载量，自签证书不在任何信任链上，用户第一次装还是那三处提示，只是「发布者」从「未知」变成「雪风」——换个字而已。
2. **要给每台机器装证书**（导入「受信任的发布者」）才会不弹，等于把负担从「点一次仍要运行」挪成「每人手动导一次证书」，更麻烦。
3. **证书与私钥要维护**：过期、丢私钥都会影响已发布版本的可信判断，还要管 pfx 密码与备份。
4. 真要消掉 SmartScreen 只有两条路：买 OV/EV 代码签名证书（要钱 + 身份审核），或者把安装包放到 Microsoft Store / 有稳定下载量的自有域名慢慢攒信誉（要时间）。

所以维持现状：**不签名 + 写清绕过办法**。等到「必须给不认识的人装」那天，再把这一节换成证书续期说明。
