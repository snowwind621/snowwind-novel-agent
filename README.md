# 雪风小说工坊

一个**以 AI 为主体**的长篇小说写作工作台：打开你自己的书库，AI 集群替你盯设定、算伏笔、写正文，人只负责拍板。

面向百万字级别连载——不是"帮你写一段"，而是"陪你写完一本书"。

![编辑器与续写](15%20文档规范/截图/01%20编辑器与续写.png)

## 它解决什么问题

长篇崩坏从来不是因为文笔，是因为**记不住**：

- 第 63 章写了"他左臂早废了"，第 80 章又让他双手端碗
- 埋了 80 个伏笔，兑现了 35 个，剩下 45 个没人记得埋在哪
- 同一个数字在三份文件里有三个版本

主流做法是"把更多上下文塞进模型"或"上 RAG"。这个项目选另一条路：

> **事实放进文件，判断交给智能体，上下文按需装配。**

## 三条铁律

### 一、一个事实只存一处

正文只在 `正文/`；随章节变的数据只在 `台账/`；稳定设定只在 `设定/`。
别处提到它们只写指针，不抄第二份。台账里两条一样的记录，早晚改一边忘另一边。

### 二、文件是正本，索引是影子

正文、设定、台账都是磁盘上的 Markdown / JSON——任何编辑器能开、能进 Git、能回滚。
程序里的索引随时可删可重建，**不允许**变成第二个真相。写入走"临时文件 → 原子改名 → Git 提交"。

### 三、记忆不等于上下文

一本百万字的书塞不进任何模型。所以：

- **设定档案**是持久数据（一个设定一个文件），永远存在
- **档案负责人格**按需唤起，任务结束就销毁
- **共享会话簿**记录谁在什么时候为哪一章改了什么，任何智能体都能检索

智能体共享的是**事实与日志**，不是上下文窗口——所以 200 个设定也不会把上下文撑爆。

## 功能

| 环节 | 能力 |
|---|---|
| 读 | 打开书库、卷/章目录、字数统计、**左侧书内文件树**（设定 / 台账 / 情节等文件直接点开） |
| 写 | 正文编辑、Ctrl+S、原子写、Git 提交、**源码 / 分屏 / 预览三态**（Markdown 实时渲染）+ 插入语法工具栏（粗体 / 标题 / 引用 / 列表 / 行内代码 / 分割线）、**AI 流式续写**、**选中改写循环** |
| 算账 | 保存后**自动同步台账**（时间线 / 出场追踪 / 承诺台账），单条 Git 提交可回滚 |
| 盯坑 | **伏笔看板**：超期 / 久置 / 待兑 / 已兑，带搁置章数 |
| 集群 | 在**设置 →「智能体集群」页签**里：6 位固定负责人 + 每位出场人物一位（可自建 / 改 / 删）、并发派活、**进度逐条推送**、总编合成「开写包」并落盘到 `情节/开写包/` |
| 对话 | **气泡消息**（你 / 总编 / 改写 / 集群 / 系统）、流式、可打断、带章节上下文、历史本地留存；每条总编回答带 **↑输入 ↓输出 · 缓存命中率**，对话头是本轮累计；**会调 AI 的动作都收在这里的「功能 ▾」**：对话 / 续写 / 改写选中 / 同步台账 / 派活 |
| 界面 | **三栏宽度可拖拽**（左 220–460 / 右 320–640，松手记住）、左栏四段：章节 / 文件 / 台账 / 建议（建议＝派活后的待裁定条目） |
| 出 | TXT / Markdown / docx / EPUB（零依赖自写 ZIP） |
| 壳 | Electron 桌面 + 浏览器预览双通道、明暗主题、**多书书架**；`npm run 打包` 出便携 exe（`99 构建产物/发布/雪风小说工坊-0.2.0-便携版.exe`） |

## 快速开始

```bash
npm install
npm run build
npm start          # 桌面窗口
```

Windows 上也可以直接双击 `启动.cmd`（桌面快捷方式指向它）。
它在 Electron 起不来时会自动退回浏览器模式，不会出现"点了没反应"。

浏览器预览（不起 Electron）：

```bash
npm run 预览        # 然后打开 http://127.0.0.1:5178
```

改完核心逻辑先跑一遍回归自检（不联网、不调模型）：`npm run 回归`。

首次运行需要填两项：**网关地址**（任意 OpenAI 兼容接口）与 **API 密钥**，在右上角「设置」里。

## 书库格式：雪风卷宗

自有格式，全中文，纯文本，离开软件也读得懂：

```
<书库根>/
  书卷.yaml                格式版本 / 书名 / 作者
  正文/
    第一卷/
      第001章 粉丝一百.md
  设定/   世界观 人物 地点 物品 势力 制度 事件 规则 备注
  台账/   时间线 出场追踪 关系线 属性变更 队伍状态 物品台账 承诺台账
  情节/   分卷大纲、细纲、开写包
  校验/ 留痕/ 考据/ 导航/ 讨论/
```

章号写在文件名里、卷号写在目录名里，不需要索引文件；台账用 Markdown 表格，软件按表头找列，你可以加列、调顺序。
完整规范见 [雪风卷宗格式](15%20文档规范/雪风卷宗格式.md)。

旧格式书库（NeuroBook 风格目录）可一次性转换，**旧目录只读不动**：
软件内「设置 → 书库迁移」，或命令行 `node 99 构建产物/导入.cjs <旧目录> <新目录>`。

## 目录结构

每个文件夹只管一件事：

| 文件夹 | 唯一职责 |
|---|---|
| `01 应用外壳` | Electron 主进程、浏览器预览、共用请求处理 |
| `02 界面渲染` | React 三栏界面 |
| `03 进程桥接` | 通道名与数据结构（唯一契约） |
| `04 模型接入` | OpenAI 兼容网关客户端、SSE |
| `05 编排内核` | 提示词组装、集群调度 |
| `06 智能体运行时` | 成员目录、上下文装配、会话簿、执行器 |
| `07 设定档案` | 伏笔状态机 |
| `09 台账同步` | 事实抽取、表格改写、写回编排 |
| `10 书库检索` | 卷宗目录 / 台账解析、看板装配 |
| `11 文件工作区` | 原子写、Git 提交 |
| `12 导出转换` | 零依赖 ZIP、TXT/MD/docx/EPUB |
| `13 共享黑板` | 事件日志 |
| `14 配置密钥` | 设置读写 |
| `16 书库迁移` | 旧格式书库转换为雪风卷宗 |
| `17 建议审阅` | 把派活回答里的修改建议抽成待裁定条目，人工拍板，绝不自动改设定 |
| `15 文档规范` | 架构说明、目录规范、截图 |

设计细节见 [架构说明](15%20文档规范/架构说明.md)。提交前跑 `npm run 整洁`，会扫密钥、大文件与垃圾文件。

## 几个踩过的坑（都写进代码了）

1. **一次问太多，推理模型会"想死机"**：把"抽事实 + 判伏笔"合成一个大提示词，8000 token 全烧在思考里，正文是空的。拆成短问句、伏笔一次喂 8 条并要求给出原文依据，同一模型 6 秒出干净 JSON。
2. **自动化不能删人的判断**：台账「兑」列原本写着作者的计划路径，程序只做追加，绝不覆盖。
3. **中文类名少个点是致命的**：`.主体 {}` 写成 `主体 {}`，那一行 CSS 静默失效，三栏布局整段塌成上下堆叠，浏览器一句错都不报。
4. **`ELECTRON_RUN_AS_NODE=1`**：带着它启动 Electron 会退化成纯 Node，窗口不出现且没有任何报错。

## 已知边界

- 续写是「从断点往下写」；改写是「选中一段 + 一句指令 → 右栏出改写版 → 点『替换原文』采纳」，可反复发起，但不自动整章重写（两个入口都在右栏「功能 ▾」里）
- 派活结果归档到讨论区，**不自动改设定卡**
- 负责人回答里关于设定/台账的修改意见会抽成 `设定/待裁定/第NNN章 建议.md`，在左栏「建议」里看；**只记录、不采纳**，没有一键应用
- 编辑器把正文按 Markdown 渲染（标题 / 引用 / 表格 / 列表 / 加粗），但**正文永远是纯文本 `.md`**：预览只读、工具栏只插语法标记，不存任何富文本
- 书架登记本机打开过的书库（路径 / 书名 / 最后打开），书库仍是一个本地目录
- 没有账号体系、云同步
